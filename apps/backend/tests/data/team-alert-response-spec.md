# 团队告警响应规范 v2.7

> 适用范围：Super AI 运维团队 | 最后更新：2026-07-25 | 审批人：ops-lead

---

## 告警等级定义

| 等级 | 响应时间 | 通知方式 | 升级条件 |
|------|----------|----------|----------|
| **P0-Critical** | 3 分钟内确认，15 分钟介入 | 电话 + 企微群 + 短信 | 30 分钟未恢复 → 通知 CTO |
| **P1-High** | 10 分钟内确认，30 分钟介入 | 企微群 + 短信 | 2 小时未恢复 → 升级为 P0 |
| **P2-Medium** | 30 分钟内确认，2 小时介入 | 企微群 | 8 小时未恢复 → 升级为 P1 |
| **P3-Low** | 工作时间处理 | 邮件 / Jira Ticket | 不升级 |

## 值班排班

- **轮换周期**: 每周一 10:00 交接
- **主值班 (Primary)**: 7×24 响应 P0/P1
- **副值班 (Secondary)**: 工作时间响应 P2/P3，主值班休假时代班
- **当前值班人查询**: 企微群发送 `/oncall who`
- **强制升级条件**: 主值班 5 分钟内未确认 → 自动通知副值班；副值班 5 分钟未确认 → 通知 ops-lead

---

## 告警聚合规则

1. 同一服务 5 分钟内触发的多条告警 → **合并为一条 Incident**，带 "burst" 标签
2. api-gateway 告警触发后，自动**抑制**其后端服务（user-service / order-service）的同因告警 — Alertmanager inhibit_rules 已配置
3. 凌晨 2:00-6:00 的 P2/P3 告警 → **降级为静默**，早上 9:00 批量推送摘要

## 处理流程模板

### P0/P1 标准处理 SOP

```
1. ACK     — 确认告警，在企微群回复 /ack <incident-id>
2. TRIAGE  — 判断是否已知问题（查 Runbook），判断影响面
3. MITIGATE — 先止损（重启/回滚/切流），不追求根因
4. RESOLVE  — 服务恢复后，60 分钟内提交初步复盘
5. POSTMORTEM — 5 个工作日内提交完整复盘文档到 KB
```

### P2 处理 SOP

```
1. ACK    — 确认告警
2. DIAG   — 在工作时间进行分析（可挂起至次日）
3. FIX    — 排入当周迭代
4. CLOSE  — 修复后在工单中备注根因和修复方式
```
