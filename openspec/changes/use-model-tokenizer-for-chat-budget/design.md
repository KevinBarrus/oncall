## Context

见 proposal.md。当前计数分散在聊天历史、运行时预算和工具压缩中，且远程 Qwen API 不提供可离线下载的精确 tokenizer。

## Goals / Non-Goals

**Goals:**

- 让所有聊天预算域共享一个计数入口。
- 模型对象提供计数能力时优先使用；否则保证中文和混合日志不会被低估。

**Non-Goals:**

- 不下载 Hugging Face 模型、不新增 tokenizer 依赖，也不改变模型或 API 配置。
- 不承诺远程 Qwen API 不公开的精确 token 数。

## Decisions

### 统一计数函数并接收可选模型计数器

计数函数接收 LangChain 消息或任意工具输出。可用时调用当前聊天模型的 token 计数方法；不可用、报错或模型不支持时，使用 `max(现有近似值, 非空白 Unicode 字符数)` 作为保守值。

这比单独接入 `transformers.AutoTokenizer` 更可靠：当前模型标识不等于 Hugging Face 模型地址，运行时下载会影响启动和离线部署。字符数回退会较早触发压缩，但不会重复出现中文按四字符一 token 的低估。

### 从已有调用点注入同一计数器

`ChatMemoryService`、运行时预算和工具压缩包装器均已经持有或可传入 `LlmProvider`，因此只替换这些共享调用点。计数器失败时不阻断聊天流程。

### 覆盖真实与回退两类测试

测试验证模型计数器会被优先调用；无计数器时，中文输入的计数不小于非空白字符数，并且工具压缩阈值、上下文预算和运行时预算走同一回退语义。

## Risks / Trade-offs

- [回退计数高估英文] → 提前压缩或更早触发保护，优先保证上下文不溢出。
- [模型计数方法不可用或不兼容] → 捕获异常并退回本地保守计数，不影响请求可用性。
- [LangChain 消息包装与供应商实际计费有差异] → 预算定位为防溢出保护；未来供应商提供 token 计数端点时可替换模型计数器。

## Migration Plan

1. 替换现有分散估算并补单元测试。
2. 运行记忆与流式聊天目标测试、Ruff 和 Pyright。
3. 若发现异常提前压缩，可回滚到旧实现；不涉及数据迁移。
