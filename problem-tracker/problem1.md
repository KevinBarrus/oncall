# 第一轮评估问题

本文件记录第一轮评估发现的全部 13 个问题。每个问题与 `solution1.md` 中同编号的解决方案对应。

## 问题1：记忆压缩输入没有独立预算

记忆压缩可能把所有未压缩消息一次性提交给 LLM，摘要请求本身可能先超过模型上下文窗口。

## 问题2：Agent 运行时上下文预算不完整

上下文估算没有完整包含工具参数、工具结果、多轮工具调用、模型输出和 LangChain 消息包装开销，95% 阈值不是真正的硬上限。

## 问题3：记忆摘要是不可验证的自由文本

摘要缺少版本、事实分类、来源消息 ID、未完成任务和质量校验，多轮压缩后可能发生事实漂移。

## 问题4：工具输出压缩可能损坏故障证据

普通 JSON 结果可能先被转成自由文本；日志压缩可能丢失时间线、trace ID、字段关系和原始结果指针。

## 问题5：同一个会话缺少并发控制

并发请求可能同时读取和更新同一个摘要边界，导致重复压缩、消息顺序不一致和上下文状态覆盖。

## 问题6：评测没有覆盖真实聊天系统

原评测直接调用检索函数和独立生成函数，没有经过真实聊天 API、会话持久化、Agent、工具调用、SSE、MCP 和权限链路。

## 问题7：评测数据集过小

当前题目、文档和场景数量不足，无法支持“某种检索策略更优”的系统级泛化结论。

## 问题8：确定性指标依赖词面重叠自动打标

Context relevance、Recall、MRR 和 NDCG 使用 token overlap 自动生成标签，指标与标签存在循环依赖，不能充分代表事实和要点覆盖。

## 问题9：LLM Judge 失败被伪装成 0.5 分

Judge 调用失败、格式错误或网络异常统一返回 0.5，导致评测异常与真实中等分数无法区分。

## 问题10：Clean-room baseline 不是严格的生成上界

当前 baseline 直接把标准答案注入上下文，更接近 answer-injection sanity check，而不是基于原始 gold 文档的真实生成上界。

## 问题11：SOP belief 存储绕过数据和租户边界

SOP belief 使用用户目录 JSON，未纳入 SQLite、Repository、事务、租户隔离、并发写入和统一审计体系。

## 问题12：SOP 成功归因范围过宽

当前可能对所有检索命中的 SOP 记录成功或失败，但被检索到不代表 SOP 被实际引用、执行或导致结果。

## 问题13：人工反馈不是幂等操作

同一用户对同一任务重复提交或重放反馈请求时，可能重复增加人工证据权重，改变 SOP 后验概率。
