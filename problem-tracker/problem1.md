# 第一轮评估问题

本文件记录第一轮实际进入修复的多个问题。每个问题与 `solution1.md` 中同编号方案对应。

## 问题1：记忆压缩输入没有独立预算

`ChatMemoryService._compact_messages()` 原先把所有未压缩消息一次性拼接后提交给 LLM。正常 Agent 的 70%/95% 上下文阈值没有限制摘要请求本身的输入，历史过长时摘要请求可能先失败，并且反复重试同一批历史。

## 问题2：Agent 运行时上下文预算不完整

原先的上下文估算只包含 system prompt、记忆摘要和 user/assistant 历史消息，没有覆盖工具参数、工具结果、多轮工具调用和模型输出预留。因此 95% 阈值不是实际请求的硬上限。

## 问题3：记忆摘要是不可验证的自由文本

原先摘要只有一段 LLM 自由文本，没有版本、分类、来源消息 ID或结构校验。多轮摘要后，事实、数字、决策和引用可能发生漂移，无法回指原始消息。

## 问题4：工具输出压缩缺少结构化证据元数据

普通 JSON 工具结果会先被序列化为自由文本，压缩结果没有统一的来源哈希、原始长度、压缩模式和原始证据关联信息。SearchLog 虽已有结构化采样，但解析失败和压缩结果的可追溯信息仍不完整。
