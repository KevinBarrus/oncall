# 问题 4：工具输出压缩可能损坏故障证据

## 评估

部分成立，中高优先级。

本次已将普通文本从“前 8000 字符截取”改为全文信号扫描、首尾保留和时间线采样；SearchLog 也已做结构化字段提取、异常聚类和重复计数。但普通聊天中的 JSON 仍会在 `streaming.py` 中序列化为文本后进入通用压缩，压缩结果仍没有统一的 sourceHash、采样范围和完整性元数据。

## 影响

trace ID、数值关系、字段结构和中间时间线仍可能丢失；调用方也不能从结果类型稳定区分完整结果、LLM 摘要和降级采样。

## 结论

评价指出的风险合理，但“当前完全是简单硬截断”已经过时；现状是专项优化后仍缺少证据级契约。
