# 第一轮修复方案与实施记录

本文件中的方案编号与 `problem1.md` 中的问题编号一一对应。

## 问题1方案：为记忆压缩增加独立输入预算

- 使用上下文窗口的 25% 作为摘要输入预算。
- 按旧消息前缀分批选择，不再一次性提交全部未压缩历史。
- 只压缩选中的旧消息，保留近期未压缩消息继续进入 Agent 上下文。
- 单条超长消息进行有界首尾保留。
- 手动压缩循环处理多个有界批次，直到当前未压缩消息处理完成。

## 问题2方案：增加 Agent 运行时预算跟踪

- 初始统计 system prompt、记忆摘要和历史消息。
- 输入安全线按上下文窗口的 90% 计算，并预留 2048 个输出 token。
- 运行期间累计工具参数、工具结果、错误结果和模型流式输出。
- 超预算时停止 Agent 继续执行，并通过 SSE 返回 `CHAT_CONTEXT_LIMIT_REACHED`。
- 当前使用 LangChain 近似 token 统计，真实模型 tokenizer 作为后续增强。

## 问题3方案：将自由文本摘要升级为结构化记忆

- 使用版本化 JSON：`version`、`summary`、`items`。
- `items` 按目标、事实、决策、待办、来源和最近上下文分类。
- 每条记忆要求保存 `sourceMessageIds`。
- 摘要进入模型前渲染为可读文本，同时保留来源信息。
- JSON、版本、分类、来源 ID或长度校验失败时，不覆盖旧摘要。
- 兼容读取旧版自由文本摘要。

## 问题4方案：为工具压缩增加结构化 envelope

- 普通字符串压缩结果增加 `content` 和 `_compression` 元数据。
- JSON 工具结果不再先转换成自由文本，压缩后保留 `preserved` 字段。
- 元数据包含 `mode`、`sourceHash`、`originalChars` 和 `compressedChars`。
- SearchLog 摘要增加结构化聚类采样模式、原始哈希和原始长度。
- 解析失败时保留 `rawPreview`；原始结果继续由审计和证据链保存。
