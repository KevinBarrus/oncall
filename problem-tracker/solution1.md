# 问题 1：解决方案

## 计划

1. 为记忆压缩定义独立预算：系统提示、已有摘要、待压缩消息、摘要输出预留和安全余量分别计入。
2. 按消息边界选择待压缩批次，不把完整历史一次性拼接进摘要请求。
3. 优先压缩较旧消息，保留最近若干轮原文。
4. 若单条消息本身超预算，按内容类型做工具结果摘要或安全降级，不截断消息边界。
5. 摘要失败时保留可重试状态和失败原因，避免无界重复提交。

## 验收标准

- 摘要请求输入始终低于独立预算。
- 超长历史可以推进压缩边界。
- 最近消息和完整原始历史不被删除。
- LLM 失败不会造成死循环。

## 实施记录

- 已在 `ChatMemoryService` 中增加独立的记忆压缩输入预算，默认使用上下文窗口的 25%。
- 压缩按旧消息前缀分批选择，不再把全部未压缩历史一次性提交给 LLM。
- 只压缩选中的旧消息，剩余近期消息继续进入本轮 Agent 上下文。
- 单条超长消息会在摘要输入中进行有界的首尾保留；SQLite 中的原始消息不变。
- 手动压缩会循环处理多个有界批次，直到当前未压缩消息处理完成。
