# 问题 5：解决方案

## 计划

1. 为聊天 session 增加 revision/version 字段。
2. 读取 session 时记录版本；更新摘要、压缩边界和消息状态时使用 CAS。
3. 同一 session 的发送、压缩和消息追加采用串行临界区。
4. CAS 冲突时重新读取状态并返回明确的“会话正在处理”或安全重试结果。
5. 多进程部署不依赖进程内锁，数据库版本校验作为最终一致性边界。

## 验收标准

- 同一 session 并发请求不会重复推进同一压缩边界。
- 摘要、消息顺序和 context_tokens 保持版本一致。
- 并发冲突可观测且不会产生静默覆盖。
